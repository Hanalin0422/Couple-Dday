# 커플 디데이 앱 디자인 구현 명세

## 1. 최우선 규칙

이 문서는 확정된 UI의 기준이다. MUST는 필수, MUST NOT은 금지 사항이다.
- 사용자 승인 없이 색상, 폰트, 크기, 배치, 메뉴 순서, 문구, 기능을 변경하거나 추가하지 않는다.
- 구현 편의, 라이브러리 기본 스타일, 개인적인 미적 판단을 이유로 디자인을 변경하지 않는다.
- 기존 기능 수정 시 요청 범위 밖의 UI를 변경하지 않는다.
- 명세에 없는 시각적 결정이나 상충하는 요구는 사용자에게 확인한다. 미확정 사항을 확정된 것으로 간주하지 않는다.
- 사용자가 변경을 승인하면 이 문서와 공통 디자인 토큰을 함께 갱신한다.

## 2. 디자인 방향

- 토스 앱을 참고한 명확한 정보 위계, 넉넉한 여백, 직관적인 조작, 면형 아이콘.
- 고급스러운 귀여움과 감성 미니멀리즘. 과도한 장식, 그림자, 테두리, 그라데이션 사용 금지.
- 온보딩의 하트 그래픽과 자동 주년 당일 및 100일 단위 자동 기념일 당일 메인 화면의 금빛 꽃가루 애니메이션은 승인된 디자인 예외이다.
- 주년 전용 디자인은 고급스러운 기념일 카드와 웨딩 타이포그래피의 분위기를 지향한다.
- 주년 전용 효과 이외의 장식 및 애니메이션을 임의로 추가하지 않는다.
- Dusty Rose 단일 라이트모드. 다크모드, 시스템 테마 자동 전환, 추가 테마를 구현하지 않는다.
- 전체 글자를 분홍색으로 처리하지 않는다. 강조 요소에만 Dusty Rose를 사용한다.
- iPhone에서 사용하는 Next.js PWA를 우선 대상으로 한다. 기술 스택과 버전은 ARCHITECTURE.md §4를 따른다.

## 4. 타이포그래피

| 영역 | 폰트 | 크기 | 굵기 |
|---|---|---:|---:|
| 온보딩/설정/기념일 제목 | 마루 부리 (MaruBuri) | 28px | 600 |
| 메인 TOGETHER | 마루 부리 | 18px | 600 |
| 디데이 숫자 | Pretendard | 72px | 700 |
| 섹션 제목 | Pretendard | 18px | 600 |
| 일반 본문 | Pretendard | 16px | 500 |
| 보조 설명 | Pretendard | 14px | 400 |
| 하단 메뉴 | Pretendard | 11px | 500 |
| 주년 숫자 | Cormorant Garamond Italic | 88px | 500 |
| 주년 한글 문구 | 마루 부리 | 38px | 400 |
| 주년 축하 문구 | Cormorant Garamond | 12px | 400 |

- 동일 위계의 제목은 폰트, 크기, 굵기, 자간, 정렬, 좌우 여백이 동일해야 한다.
- 일반 페이지 제목은 왼쪽 정렬. 메인의 TOGETHER는 중앙 정렬 예외이다.
- 실제 마루 부리 및 Pretendard 폰트를 적용한다. 시안의 일반 serif는 미리보기용 대체 폰트였으며 최종 구현 기준이 아니다.
- 폰트 파일은 확보했으며 경로·출처·라이선스(SIL OFL 1.1)는 ARCHITECTURE.md §4.2에 기록한다. 임의의 대체 폰트를 최종 디자인으로 확정하지 않는다.
- 자동 주년 당일에는 일반 디데이 숫자 대신 주년 전용 타이포그래피를 사용한다.
- 주년 숫자와 한글 '주년'은 동일한 행에 배치한다.
- 주년 숫자는 Cormorant Garamond Italic을 사용하고, 한글 '주년'은 마루 부리를 사용한다.
- 주년 숫자와 한글 문구의 색상은 text-primary(#191F28)로 유지한다.
- HAPPY ANNIVERSARY는 Cormorant Garamond, 12px, 400, 자간 2px, accent(#B57889)를 사용한다.
- 두 자릿수 이상의 주년은 원형 내부 가용 너비에 맞춰 글자 크기를 비례 조절한다.
- 주년 문구는 줄바꿈, 말줄임표, 잘림 없이 표시한다.
- Pretendard, MaruBuri, Cormorant Garamond 폰트는 로컬 리소스로 관리하며 오프라인에서도 동일하게 표시한다.

## 5. 공통 레이아웃 및 컴포넌트

| 항목 | 기준 |
|---|---|
| 화면 좌우 여백 | 24px |
| 카드 모서리 | 20px |
| 카드 내부 여백 | 16~20px |
| 섹션 간격 | 32px 기준 |
| 주요 버튼 높이 | 52~56px |
| Bottom Sheet 모서리 | 24~28px |
| 메뉴 행 높이 | 52~56px 기준 |

공통 PageHeader, BottomNavigation, Card, Button, Input, SegmentedControl, ProfileAvatar 컴포넌트를 재사용한다. 컴포넌트 명칭은 구현 예시이며 구조 자체는 유지한다. 디자인 토큰은 중앙에서 관리하고 페이지별 중복 선언을 피한다.

- 아이콘: 하단 메뉴는 마지막 통합 시안의 면형 설정(톱니), 하트, 달력 아이콘. 편집 등 기능은 간결한 라운드 라인 아이콘, 감성 그래픽은 제한적으로 사용한다.
- 하단 내비게이션 순서: 설정 / 하트 / 기념일. 가운데는 글씨 없이 하트만 표시한다. 활성 메인 하트는 accent, 활성 설정/기념일은 짙은 본문색, 비활성은 icon-inactive.
- 일반 화면에서 하단 내비게이션의 높이, 위치, 배경, 아이콘 스타일을 동일하게 유지한다.
- 기본 진입은 메인. 설정은 왼쪽, 기념일은 오른쪽. 좌우 스와이프와 하단 메뉴 전환을 지원하는 방향을 유지한다.
- 온보딩에는 하단 내비게이션이 없다.
- 실제 iOS 상태바와 홈 인디케이터를 HTML로 복제하지 않는다. 시안의 9:41 등은 기기 프레임 예시이다.
- iPhone Safe Area를 고려한다. 메인은 뷰포트 안에 콘텐츠 전체를 배치하고 문서 스크롤 자체가 발생하지 않게 한다. 설정/기념일은 콘텐츠 영역만 스크롤하고 하단 메뉴를 고정한다. 기념일의 제목과 필터도 고정한다. 스크롤바는 평상시 노출하지 않는다.
- 작은 화면에서는 메인 원형 크기와 여백을 조절하되 콘텐츠를 자르거나 단순히 overflow로 숨기지 않는다.

### 5.0 공통 반응형 기준 (2026-11-26 사용자 요청으로 정립)

- 위 표와 4절의 수치는 시안 기준 기기(390×844)의 기본값이다.
- 모든 화면(온보딩·메인·설정·기념일), 하단 메뉴, Bottom Sheet 는 하나의 공통 단위 `--u`(시안 1px)를 사용한다. `--u = min(앱 프레임 폭 ÷ 390, 앱 프레임 높이 ÷ 720)`, 0.5~1.15px 범위.
- 페이지별 독립 배율(scale/zoom)이나 특정 요소만 따로 조절하는 방식을 사용하지 않는다.
- 앱 프레임은 최대 폭 480px 이며 넓은 화면에서는 가운데 표시한다. 상단 Safe Area 는 프레임 콘텐츠 영역, 하단 Safe Area 는 하단 메뉴에서 한 번만 반영한다.
- 터치 영역은 최소 44×44px, 글자는 최소 크기(본문 14px, 보조 12px, 하단 메뉴 10px, 입력 16px)를 보장한다.
- 같은 viewport 에서는 화면을 전환해도 하단 메뉴의 크기와 위치가 같다.

### 5.1 앱 이름 및 홈 화면 아이콘 (2026-11-26 사용자 승인)

- 앱 표시 이름: **D-Day** (manifest name/short_name, apple-mobile-web-app-title, 문서 제목).
- 아이콘 원본: `src/app/icon.svg`. background(#FFF8FA) 바탕 위 Dusty Rose 계열 광택 하트와 작은 4각 반짝임 2개. 온보딩 하트 그래픽과 같은 결의 토스 스타일.
- 아이콘의 그라데이션·광택·그림자는 온보딩 하트와 같은 승인된 그래픽 예외이며 앱 내부 UI에는 적용하지 않는다.
- 파생 PNG: `public/icons/apple-touch-icon.png`(180), `icon-192.png`, `icon-512.png`, `icon-maskable-512.png`(원형 마스크 안전 영역용 80% 배치). `npm run icons`로 재생성한다.

## 6. 온보딩

초기 설정 미완료 시에만 표시한다. 완료 후 재실행 및 업데이트 시 메인으로 바로 진입한다.

위에서 아래 순서:
1. 왼쪽 상단 Dusty Rose 하트 그래픽과 작은 반짝임.
2. 왼쪽 정렬 제목: “우리의 시간을” / “시작해 볼까요?” (두 줄).
3. 보조 문구: “함께한 첫날부터 소중한 순간까지.”
4. 중앙에 내 프로필 / 작은 하트 / 상대방 프로필. 원형 아바타 우측 하단에 + 아이콘. 사진은 선택 사항.
5. 내 이름, 상대방 이름 입력 필드. placeholder: “이름 또는 애칭”.
6. “처음 사귄 날” 날짜 선택. placeholder: “날짜 선택”.
7. “시작일 계산 방식” 세그먼트: 0일부터 / 1일부터. 기본 1일부터.
8. “시작하기” 버튼. 두 이름과 시작일이 유효할 때만 활성화.
9. “기존 데이터 복원하기” 텍스트 진입점.

별도 환영 페이지, 튜토리얼, 테마 선택, 로그인 화면을 임의로 추가하지 않는다. 입력 저장 성공 후 완료 상태를 기록하고 메인으로 이동한다. 설정 변경이나 프로필 삭제로 온보딩을 다시 표시하지 않는다. 데이터 초기화 또는 전체 데이터 유실 시에는 온보딩으로 진입한다. 정상 백업 복원 후 메인으로 이동한다. 완료 상태와 저장 데이터 유효성을 함께 확인한다.

## 7. 메인 화면

스크롤 없는 단일 화면. 다음 순서와 중앙 정렬을 유지한다.

1. TOGETHER (Dusty Rose, 자간을 넓게).
2. 원형 디데이 진행률. 12시 방향부터 시계 방향으로 채우며 끝은 둥글게. 시안 기준 원형 SVG 272×272, 반지름 121, 트랙 5, 진행선 7 (반응형 비례 조정).
3. 원 내부 위에서 아래:
   - 일반 날짜: “우리가 함께한 지”, 큰 디데이 숫자, “DAYS”, 연애 시작일(YYYY.MM.DD).
   - 자동 주년 당일: “우리가 함께한 지”, “N주년”, “HAPPY ANNIVERSARY”, 연애 시작일(YYYY.MM.DD).
   - 주년 숫자 및 한글 문구는 4절의 주년 전용 타이포그래피를 적용한다.
   - 주년 당일에는 일반 디데이 숫자와 DAYS를 표시하지 않는다.
   - 주년 당일 원형 진행률은 100%로 표시한다.
   - 주년 표시 여부에 따라 원형 크기, 프로필 위치, 하단 내비게이션 및 전체 레이아웃을 변경하지 않는다.
4. 원 아래 내 프로필 / 작은 하트 / 상대방 프로필. 각 프로필 아래 이름. 시안 기준 원형 사진 76px.
5. 고정 하단 내비게이션.

다음 기념일까지 남은 일수나 기념일 이름을 메인에 별도로 표시하지 않는다. 사진이 없으면 지정된 기본 프로필을 사용한다. 원형 진행률은 다음 자동 기념일을 향한 진행을 표현한다. 세부 계산은 10절 참조.

### 7.1 자동 주년 당일 전용 디자인

- 1주년, 2주년, 3주년 및 이후 모든 자동 주년에 동일한 디자인을 적용한다.
- 주년 숫자는 우아한 이탤릭 세리프체로 강조하고 한글 '주년'은 마루 부리로 표현한다.
- 기존 TOGETHER, 상단 안내 문구, 연애 시작일, 프로필, 하트, 하단 내비게이션을 유지한다.
- 일반 날짜에는 기존 디데이 디자인을 그대로 사용한다.
- 100일, 200일 등 자동 일수 기념일과 사용자 지정 기념일에는 주년 전용 디자인(타이포그래피)을 적용하지 않는다.
- 단, 100일 단위 자동 기념일(100일, 200일, 300일 …) 당일에는 일반 디데이 디자인을 유지하면서 7.2절의 금빛 꽃가루 효과를 주년과 같은 규칙으로 적용한다(2026-11-26 사용자 승인). 10·30·50일과 사용자 지정 기념일에는 적용하지 않는다.
- 자동 일수 기념일과 자동 주년이 동일한 날짜에 존재하면 메인에서는 주년 전용 디자인을 우선한다.

### 7.2 주년 축하 애니메이션

| 항목 | 디자인 기준 |
|---|---|
| 효과 | 금빛 꽃가루 및 작은 4각 별빛 |
| 입자 개수 | 약 65개 |
| 입자 기본 크기 | 2~6px |
| 입자 형태 | 작은 타원형 꽃가루와 4각 별빛 혼합 |
| 색상 | celebration 계열 디자인 토큰 |
| 움직임 | 좌우로 살랑거리며 천천히 낙하 |
| 회전 | 입자별 자연스러운 미세 회전 |
| 밝기 | 은은한 반짝임 및 투명도 변화 |
| 지속 시간 | 약 15초 (2026-11-26 7초에서 변경 승인) |
| 종료 | 자연스럽게 투명해지며 제거 |
| 사운드 | 없음 |
| 표시 영역 | 메인 화면 위의 독립적인 오버레이 |

- 자동 주년 당일 및 100일 단위 자동 기념일 당일 메인 화면 최초 진입 시 자동 재생한다.
- 같은 날 설정 및 기념일 화면을 다녀와도 자동으로 반복 재생하지 않는다.
- 대상 날짜에는 원형 디데이 영역을 터치하면 축하 효과를 다시 재생한다.
- 별도의 재생 버튼을 화면에 추가하지 않는다.
- 애니메이션은 화면 레이아웃에 영향을 주지 않는다.
- 애니메이션 오버레이는 터치 및 스와이프를 가로채지 않는다.
- 애니메이션 도중에도 하단 메뉴 및 화면 이동 기능을 정상 사용할 수 있어야 한다.
- 모션 감소 설정이 활성화된 환경에서는 자동 재생하지 않는다. 사용자가 원형 디데이 영역을 직접 터치하면 재생한다(2026-11-26 사용자 승인).
- 무한 반복, 과도한 폭죽, 화면 흔들림, 배경색 변경, 사운드를 추가하지 않는다.
- 애니메이션 종료 후에는 주년 전용 타이포그래피만 유지한다.
- 주년 당일이 지나면 기존 메인 화면으로 복귀한다.

## 8. 설정 화면

제목 “설정”. 기념일 화면과 동일한 PageHeader 사용.

카드 순서:
1. 프로필 및 정보: 중앙에 두 원형 프로필과 하트. 사진 우측 하단 카메라 아이콘. 아래 메뉴는 내 이름 / 상대방 이름 / 연애 시작일. 오른쪽에 현재 값과 chevron.
2. 디데이 설정: “시작일 계산 방식”, 0일부터 / 1일부터 선택, “처음 사귄 날을 N일로 계산해요.” 안내.
3. 화면 꾸미기: 팔레트 아이콘, “테마”, “Dusty Rose”. 현재 단일 테마이므로 다른 테마 선택 화면은 구현하지 않는다. 기존 시안의 테마 행은 유지하되 실제 조작 가능 여부는 확인 필요.
4. 데이터 관리: 데이터 백업 / 데이터 복원 / 데이터 초기화. 초기화는 danger 색상.

카드는 흰색, 둥근 모서리. 각 메뉴 사이 불필요한 구분선 제거. 자동 기념일 설정 메뉴는 추가하지 않는다. 데이터 관리 기능은 유지한다. 백업/복원/초기화 기능 정책은 REQUIREMENTS.md §11~13, 백업 형식은 ARCHITECTURE.md §10을 따르며, 확인 UX의 상세 배치는 사용자 확인 대상이다.

## 9. 기념일 화면

- 제목 “우리의 기념일”, 우측 + 아이콘(기념일 추가 진입점).
- 제목 아래 필터: **지난 날 / 전체 / 다가오는 날**. 반드시 이 순서, 동일 너비, 기본 선택 가운데 전체. 선택 영역은 흰색, 나머지는 input 색상.
- 시간 오름차순 세로 타임라인. 왼쪽 연결선과 점, 오른쪽 카드. 과거는 위, 미래는 아래. 전체 진입 시 오늘과 가까운 기념일 위치를 표시한다. 이전/이후 버튼은 시안의 스크롤 대체 수단이었으므로 실제 UI에는 넣지 않는다.
- 지난 기념일: 이름, 날짜, 사진 추가 아이콘. 저장된 사진은 카드에서 조회하고 접기/펼치기 가능. 추억 사진 등록 기능 유지. 사진이 없는 경우 임의의 예시 사진을 넣지 않는다.
- 오늘: “오늘 · N일째”와 가로 구분선.
- 다음 기념일: 강조색 카드, “다가오는 기념일”, 기념일 이름, 우측 큰 D-N, 날짜, 하단 진행률 바.
- 이후 기념일: 흰 카드, 기념일 이름, 날짜, 우측 D-N.
- 지난 날 필터는 지난 기념일 및 추억, 전체는 과거/오늘/미래, 다가오는 날은 예정된 기념일을 표시한다.
- 상단 제목 및 필터와 하단 내비게이션 고정. 타임라인만 실제 세로 스크롤.
- 사진 등록 Bottom Sheet는 기존 시안처럼 상단 손잡이, 기념일명, “소중한 순간을 남겨보세요”, 사진 추가 안내, “사진 선택하기”, “다음에” 순서. 라이트모드만 사용한다.

## 10. 날짜 및 자동 기념일

확정된 자동 기념일: 10일, 30일, 50일, 100일, 200일, 300일, 1주년, 400일, 500일, 600일, 700일, 2주년, 이후 계속.

- 100일 이후에는 100일 단위의 자동 일수 기념일을 계속 생성한다.
- 자동 주년 기념일은 매년 생성한다.
- 기본 시작일 계산은 1일이며 사용자가 0일로 변경할 수 있다.
- 디데이 계산은 달력 날짜 차이 + 시작일 오프셋(0 또는 1)을 사용한다.
- N일 기념일은 시작일 + (N - 오프셋)일로 계산한다.
- N주년은 원래 연애 시작일의 달력상 N년 뒤 날짜로 계산한다.
- 2월 29일에 시작한 경우 평년에는 2월 28일, 윤년에는 2월 29일을 주년으로 처리한다.
- 모든 기념일은 실제 날짜순으로 정렬한다.
- 동일한 날짜에 여러 기념일이 존재하면 각각 표시하되 진행률 목표 날짜는 하나로 처리한다.
- 메인 원형 진행률은 자동 기념일만 포함하여 계산한다.
- 기념일 화면 강조 카드의 진행률은 자동 및 사용자 지정 기념일을 포함하여 별도로 계산한다.
- 첫 기념일 이전의 진행률은 연애 시작일을 기준으로 계산한다.
- 기념일 당일에는 해당 진행률을 100%로 유지하며 다음 날부터 다음 구간으로 전환한다.
- 기념일 당일은 전체 및 다가오는 날 필터에 포함한다.
- 날짜와 D-N은 실제 설정값에서 계산하며 시안의 예시값을 하드코딩하지 않는다.

### 10.1 주년 당일 표시 규칙

- 자동 주년 여부는 누적 일수가 아닌 실제 달력 날짜로 판단한다.
- 시작일 계산 방식(0일/1일)은 주년 날짜에 영향을 주지 않는다.
- 자동 주년 당일에는 메인 화면에 N주년 및 HAPPY ANNIVERSARY를 표시한다.
- 내부 디데이 계산값은 숫자로 유지한다.
- 자동 주년 당일에는 7.2절의 축하 애니메이션을 적용한다.
- 자동 일수 기념일 및 사용자 지정 기념일은 주년 표시 여부에 영향을 주지 않는다.
- 주년 다음 날부터 일반 디데이 숫자 및 DAYS 표시로 복귀한다.
- 주년 전용 디자인은 메인 화면에만 적용한다.
- 세부 날짜 계산 및 예외 처리는 REQUIREMENTS.md와 ARCHITECTURE.md를 따른다.

## 12. 명세 범위 및 미확정 사항

이 문서는 확정된 디자인과 화면별 UI 규칙을 고정한다.

일반 날짜의 메인 디자인 및 자동 주년 당일의 전용 타이포그래피와 금빛 꽃가루 애니메이션은 확정 디자인에 포함된다.

실제 픽셀 렌더링은 기기 크기와 폰트 렌더링 환경에 따라 달라질 수 있으나 확정된 정보 위계, 색상, 배치 및 분위기를 유지해야 한다.

기능 정책은 REQUIREMENTS.md, 시스템 및 데이터 구조는 ARCHITECTURE.md를 따른다.

아직 확정되지 않은 상세 UI 및 구현 세칙은 사용자에게 확인한다. 기존 문서에서 이미 확정된 기능을 다시 미확정 사항으로 취급하지 않는다.
